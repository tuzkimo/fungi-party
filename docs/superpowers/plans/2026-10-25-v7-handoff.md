## 一句话现状

联机的**地基、共享森林、邀请、教室和传炸弹上服务器**都做完了：自己的 Linux 服务器上跑账号/存档/钱包/抽卡，
森林里能看见别人走动，同屏 2P 也是世界里的一份子，两个人能互相邀请进同一局（教室、传炸弹是服务器判的）。
**还没做**：猫头鹰 / 赛跑搬到服务器（照第 3 步的模子），睡觉一天一次。

- 分支：`v7-online`（未推送，本地领先 main 11 个提交）
- 主线提交：包信封 / 口令派生 / 账号记录 → 服务器 op → 无头服务器 + 客户端 + 启动菜单 → 共享森林 → 房间骨架
  → 邀请与会话消息（`7375909`）→ 教室上服务器（`9ec2946`）→ 传炸弹上服务器（`81f4326`）
- **二期进度：第 1、2、3、3.5、4 步已完成；下个会话按第 5~6 步搬剩下两款。**

冒烟通过的最后三步应该是：`共享森林：A 看见 1 份（含 2P），B 看见 A 和 A 的 2P`，
`邀请：两人进同一间教室各扣 12 体力，服务器判吃口，收局结账 N 币`，
`传炸弹：两人同局各扣 25 体力，服务器判投掷，收局结账 N 币`，然后 `SMOKE OK`。

## 硬约束（目标机器变了，这几条跟着变）

目标机器：**2 核 2G、5 Mbps 出口、和别的项目混部**；实际同时在线 **3~4 人**。

| 项 | 值 | 依据 |
|---|---|---|
| 森林上限 | **8 人**（`server_main.gd` 的 `DEFAULT_MAX`） | 实测 8 人全量广播 1.1 Mbps，留 4 Mbps 余量 |
| 同时开的小游戏房 | **1 间** | 实测 30 人森林 0.4 核；这台机器只够森林 + 1 房 |
| 一局座位 | **4 个**（四款游戏都是 4 座） | 本地座位先占：0 = 主机、1 = 本地 2P；远端按接受顺序往后，剩下的填人机 |
| 服务器上的小游戏 | **只跑 RefCounted 模型，绝不实例化 3D 场景** | 一个 Godot 无头进程 94 MB 常驻；一个 Node3D 房间就是几十 MB，两个就吃光 |
| 单包 | < 8 KB（8 人快照约 1.7 KB） | 超长包现在会在 `_send` 里 `push_error`，不会静默丢 |

**明确不做**（别再讨论）：16/32 人的世界、距离裁剪、分线、世界持久化、陌生人匹配、排行、交易。
哪天真的超过 8 人，先做「只发附近的玩家 + 远端降 5 Hz」，那是另一个决定。

### 2. 邀请与会话消息（通到「两个人进同一局」）✅ 已完成（`7375909`）

动手前先看这几处（现成的形状，别重新设计）：

- `game/net/protocol.gd` 的 `Msg` 枚举：新类型**追加在末尾**，老序号不能动。
- `game/net/client.gd`：`request()` 排进 `_queue`，一次只飞一条（`_inflight`），**只有 `OP_RESULT` 会清 `_inflight`**；
  `WORLD` 在 `_drain()` 里就地处理，顺手 `world.erase(me)` / `world.erase(me|1)`。
- `game/net/server_main.gd`：`_sessions[id]` 是每连接的字典（`name` / `authed` / `slots`），
  `_broadcast_world()` 已经**按人**发（各自一份 WORLD），邀请塞进去最省事。
- `game/net/ops.gd`：只处理**存档**类 op，纯函数、不碰会话状态。

四个会踩的点（已经查清楚，照这个做）：

1. **`invite` / `answer` 不能放进 `NetOps`**：它是对存档的纯函数，没有会话/房间状态可看。
   在 `server_main.gd` 的 `_on_op` 里先匹配这两条（走一份 `ROOM_OPS` 白名单），不命中再交给 `NetOps.apply`。
2. **这两条也必须回一条 `OP_RESULT`**（`{op, ok, error, result, save}`），哪怕什么都没改存档：
   客户端 `_inflight` 只认 `OP_RESULT`，不回就是 10 秒后 `timeout` 掉线。`save` 随便填 `Accounts.read()` 那份。
3. **`WORLD` 里加 `invites: []`** 每人一份：`{from: String, kind: String}`。客户端 `_drain` 里读进 `invites`，别塞进 `world`。
4. **`VERSION` 要 +1**：`Msg` 枚举加值本身是安全的，但老服务器对不认识的 `t` 走 `_handle` 的 `_:` → `ERROR{reason:"kind"}`
   → 客户端 `_dead` 掉线。加版本号让「客户端新、服务器旧」变成握手期就拒连，不要跑到局中才莫名其妙掉线。

体力按 kind 取现成常量：`STAMINA_COST_CLASSROOM` / `_BOMB` / `_OWL` / `_RACE`，
校验用 `Day.can_play(stamina, cost)`、扣用 `Day.spend_cost(stamina, cost)`。
规矩：**谁玩谁付自己的**——邀请方在 `invite` 时查一次，被邀请方在 `answer(accept)` 时查一次，
成局那一下才扣（`answer` 拒绝/超时就一分不扣）。因为 `Day.spend_cost` 在 `NetOps._spend_stamina` 里已有一份，
这里不要复制公式，直接调 `Day`。

客户端 `NetClient` 要加的：`invites`、`session`（一局快照）、`send_input(payload)`、`signal join_room`。
`send_input` 学 `send_move`——**走独立消息，不排 op 队列**（输入比 op 新，堵在队列后面就是网络延迟翻倍）。

- `NetProtocol.Msg` 加：`INVITE`（服务器→客户端）、`SESSION`（服务器→客户端，一局的状态快照）、`INPUT`（客户端→服务器）
- `WORLD` 快照里带 `invites: []`（谁邀请我，带 kind 和发起人）
- 服务器 op 加两条：`invite {to, kind}`、`answer {from, kind, accept}`
  - 校验：对方在线、不是自己、自己的体力够开局、没有正在进行的房、1 房上限
  - 成局：建 `NetRoom`，给参与的账号各发 `SESSION {kind, seats, seed}`，客户端据此 `change_scene_to_file`
- `NetClient`：`invites`、`room`（一局的快照）、`send_input(payload)`、`join_room` 信号
- 测试：`tests/test_net_invite.gd` 覆盖拒绝路径（不在线 / 体力不够 / 已在房里）
- 验收：两个客户端互相邀请 → 都进到同一个场景（哪怕场景还是旧的单机逻辑）

#### 第 4 步踩出来的三件事（第 5 步照这个走）

- **快照可以把「上次之后发生的事」一起发**（`BombRound.snapshot()` 里的 `events`，发完就清）。
  客户端不用自己推演「谁扔的、谁炸了」，直接照事件放音效和飞行演出。代价是**一帧只能拍一次快照**：
  `server_main._push_session` / `_broadcast_session` 已经改成拍一次再各人 `duplicate(true)`，
  否则第一个收到的人把事件吃光，第二个人什么都看不到。
- **拍一下就生效的输入（投掷、按键这类）在 `NetRoom.input()` 里直接交给模型，不排到 tick**；
  「按着」类照旧攒进 `_inputs`、由 `tick()` 造 `press` 数组。`tick()` 里按 kind 分叉。
- **传炸弹在服务器上没有倒数**：`BombRound` 里没有 countdown，服务器一成局引信就开烧，
  所以客户端那一局跳过本机 3 秒倒数、直接把投掷键解除保险。教室的倒数在 `ClassroomRound` 里，两者本来就不一样。

## 第 2、3 步做完之后多出来的约定（下一步照着走，别再重新设计）

- 邀请、成局、结账、`leave_room` 全在 `game/net/lobby.gd`：它是纯逻辑，存档读写由服务器注入 `Callable`，
  所以 `tests/test_net_invite.gd` 不用起服务器。加新 op 先想清楚「这个数客户端说了算吗」，再决定放进
  `NetOps`（存档纯函数）还是 `ROOM_OPS`（要会话/房间状态）。
- 邀请不新开消息类型：跟 `WORLD` 一起按人发（`invites: [{from, kind}]`）。
- 一款游戏搬上服务器 = 写一个 `*_round.gd`（RefCounted，tick 顺序照抄本地场景的 `_process`）
  + `NetRoom._build_model()` 里加一条 + 客户端场景加「服务器那一局」分支。
  客户端**不自己 tick、不扣体力、不结账**，只把快照写进本地那几个模型对象再照旧渲染，输入走 `send_input`。
- 结账在 `NetLobby._settle()`，只结一次；over 那一帧的快照会带上各人刚入账的存档，
  客户端 `_on_session` 顺手刷镜像 —— 币进账不用再单独发一条 op。
- 客户端进没进局只看 `_ready` 那一次（`classroom.gd` 的 `_joinable_room()`）：
  over 之后快照还留着给演出用，不能中途退回「本地自己算」。
- 局内快照 20 Hz（`Config.NET_ROOM_HZ`），硬顶 300 秒（`NET_ROOM_MAX_SECONDS`），邀请活 20 秒
  （`NET_INVITE_SECONDS`）。这些数字都在 `Config`。

## 已知的坑（踩过一次，别再踩）

1. **`add_coins` 是临时口子**：一期小游戏还在客户端跑，收益只能客户端上报（上限 200）。
   每款小游戏搬到服务器后，顺手把那份场景里的调用删掉；四款都搬完就从 `NetOps.CLIENT_OPS` 里删掉它。
2. **老本地存档没有导入账号**：第一次联网是新号，本地的币和皮肤不会带过去。这是有意的（客户端报自己的币 = 后门）。
   要的话做一个服务器侧运维命令手工灌，别做客户端导入按钮。
3. `Save.remote` 非空 = 联机镜像模式。镜像能随便读，**写只能走 op**；`Save.write()` 在联机模式下只推天色。
4. 座位规则：人类占 `0..n-1`，人机从 `n` 往后；找某号座位用 `Player.of_seat()`，别拿 `get_first_node_in_group("player")`。
5. 浮层里动态拼的文字只用 ASCII 标点（真机系统字体没有全角括号）。
6. 客户端与服务端必须同版本：`NetProtocol.VERSION` 一变老客户端就连不上。
7. 服务器重启会踢掉所有在线的人（没有重连，一期明确不做）。
8. 两个 `godot` 进程共用 `user://` 会互相踩存档 —— 测试/工具一律用独立 `--saves` 目录。
9. **客户端一次只飞一条 op（`_inflight`），且只有 `OP_RESULT` 能清它。** 服务器收到一条 op 不回包，
   10 秒后客户端就 `timeout` 掉线。新增任何 op 都必须回 `OP_RESULT`（即使没改存档）。
10. 老服务器收到不认识的 `t` 不是忽略而是回 `ERROR{reason:"kind"}`（客户端跟着 `_dead`），
    所以**客户端先上线、服务器后部署**会变成「一连就掉」。两边一起发版。
