## 一句话现状

联机的**地基和共享森林做完了**：自己的 Linux 服务器上跑账号/存档/钱包/抽卡，森林里能看见别人走动，
同屏 2P 也是世界里的一份子。**还没做**：邀请真人进同一局、四款小游戏搬到服务器跑。

- 分支：`v7-online`（未推送，本地领先 main 6 个提交）
- 主线提交：包信封 / 口令派生 / 账号记录 → 服务器 op → 无头服务器 + 客户端 + 启动菜单 → 共享森林

## 硬约束（目标机器变了，这几条跟着变）

目标机器：**2 核 2G、5 Mbps 出口、和别的项目混部**；实际同时在线 **3~4 人**。

| 项 | 值 | 依据 |
|---|---|---|
| 森林上限 | **8 人**（`server_main.gd` 的 `DEFAULT_MAX`） | 实测 8 人全量广播 1.1 Mbps，留 4 Mbps 余量 |
| 同时开的小游戏房 | **1 间** | 实测 30 人森林 0.4 核；这台机器只够森林 + 1 房 |
| 一局座位 | **4 个**（四款游戏都是 4 座） | 本地座位先占：0 = 主机、1 = 本地 2P；远端按接受顺序往后，剩下的填人机 |
| 服务器上的小游戏 | **只跑 RefCounted 模型，绝不实例化 3D 场景** | 一个 Godot 无头进程 94 MB 常驻；一个 Node3D 房间就是几十 MB，两个就吃光 |
| 单包 | < 8 KB（8 人快照约 1.7 KB） | 超长包现在会在 `_send` 里 `push_error`，不会静默丢 |

**明确不做**（别再讨论）：16/32 人的世界、距离裁剪、分线、世界持久化、陌生人匹配、排行、交易。
哪天真的超过 8 人，先做「只发附近的玩家 + 远端降 5 Hz」，那是另一个决定。

## 下一步（按这个顺序做，每步独立可玩）

### 1. 房间骨架（服务器侧，纯逻辑）

- 新建 `game/net/room.gd`：`class_name NetRoom extends RefCounted`
  - `static func create(kind: String, humans: Array[String]) -> NetRoom`：`humans` 是账号名，按本地优先排好序
  - 字段：`kind`、`seats`（长度 4，每格 `{account: String, npc: bool}`）、`model`、`elapsed`、`over`
  - `func tick(delta: float) -> void`、`func snapshot() -> Dictionary`、`func input(account: String, payload: Dictionary) -> void`
  - `kind` 取值：`classroom` / `bomb` / `owl` / `race`
- 测试 `tests/test_net_room.gd`：人机补齐、座位顺序（本地在前）、快照字段齐全、满员拒绝
- 验收：`bash scripts/test.sh` 通过；此时还没有任何网络接线

### 2. 邀请与会话消息（通到「两个人进同一局」）

- `NetProtocol.Msg` 加：`INVITE`（服务器→客户端）、`SESSION`（服务器→客户端，一局的状态快照）、`INPUT`（客户端→服务器）
- `WORLD` 快照里带 `invites: []`（谁邀请我，带 kind 和发起人）
- 服务器 op 加两条：`invite {to, kind}`、`answer {from, kind, accept}`
  - 校验：对方在线、不是自己、自己的体力够开局、没有正在进行的房、1 房上限
  - 成局：建 `NetRoom`，给参与的账号各发 `SESSION {kind, seats, seed}`，客户端据此 `change_scene_to_file`
- `NetClient`：`invites`、`room`（一局的快照）、`send_input(payload)`、`join_room` 信号
- 测试：`tests/test_net_invite.gd` 覆盖拒绝路径（不在线 / 体力不够 / 已在房里）
- 验收：两个客户端互相邀请 → 都进到同一个场景（哪怕场景还是旧的单机逻辑）

### 3. 教室上服务器（第一款，做完这套就通了）

- 服务器 `NetRoom` 里按 `kind == "classroom"`：持 `StealEat` + `Gaze` + `NpcSeat[]`，每 tick 推进，
  `snapshot()` 给 `{time_left, over, seats: [{bites, caught, stun, out}], gaze: {phase, target, watching}}`
- 客户端 `game/minigame/classroom.gd`：`NetClient.room` 非空时**不自己 tick**，
  把快照写进本地的 `StealEat.Seat` 字段再照旧渲染（`_seats[i].apply(...)`、`_ui.set_state(...)`），
  输入用 `send_input({press: bool})` 上报自己那个座位
- 结算由服务器发：`SESSION` 里带 `{coins: N}`，客户端只放演出；**顺带删掉这份场景里 `Save.add_coins` 的调用**
- 验收：单人（另 3 个座位是人机）能完整打完并通过服务器拿到币；两人同场能看见对方的吃口数

### 4. 传炸弹 → 5. 猫头鹰 → 6. 赛跑

照第 3 步的模子做。赛跑多一步：

- **先把 `RacePlayer`（`CharacterBody3D` + `move_and_slide`）换成纯数学模型**（和 `RaceRacer` 共用赛道与撞击判定），
  跳跃退化成「y 够高就跨过矮栏」的判定；**离线模式一起换**，`RACE_*` 参数要重调一遍手感
- 这是唯一一处会改变单机玩法的改动，做完要人肉验手感

### 7. 睡觉一天一次

接上服务器世界时钟（`server_main.gd` 的 `_world_clock` 已经在算了，客户端 `NetClient.clock` 也有）后，
把 `NetOps._sleep` 的 `shortcut:` 注释里那条欠账补掉：一天只能睡一次，只重置自己的体力，不动天色。

## 已知的坑（踩过一次，别再踩）

1. **`add_coins` 是临时口子**：一期小游戏还在客户端跑，收益只能客户端上报（上限 200）。
   每款小游戏搬到服务器后，顺手把那份场景里的调用删掉；四款都搬完就从 `NetOps.CLIENT_OPS` 里删掉它。
2. **老本地存档没有导入账号**：第一次联网是新号，本地的币和皮肤不会带过去。这是有意的（客户端报自己的币 = 后门）。
   要的话做一个服务器侧运维命令手工灌，别做客户端导入按钮。
3. `Save.remote` 非空 = 联机镜像模式。镜像能随便读，**写只能走 op**；`Save.write()` 在联机模式下只推天色。
4. 座位规则：人类占 `0..n-1`，人机从 `n` 往后；找某号座位用 `Player.of_seat()`，别拿 `get_first_node_in_group("player")`。
5. 浮层里动态拼的文字只用 ASCII 标点（真机系统字体没有全角括号）。
6. 客户端与服务端必须同版本：`NetProtocol.VERSION` 一变老客户端就连不上。
7. 服务器重启会踢掉所有在线的人（没有重连，一期明确不做）。
8. 两个 `godot` 进程共用 `user://` 会互相踩存档 —— 测试/工具一律用独立 `--saves` 目录。

## 还没被验证过的东西

- 小游戏房间的 CPU/内存成本**没实测**（还没实现）；实现后要用 `tools/net_load.gd` 的思路压一次
